Foundry reads ten kinds of source, and takes data your apps and agents send to an
[API source](/foundry/data/api-sources). Apps sync every table their credential can
read; databases and Amazon S3 sync the tables you choose. Every credential only needs
read access, and every plan offers every kind: plans differ in
[how often they sync](/foundry/data/connect-data#syncs-on-a-schedule).

| Source | Credential | Syncs |
| --- | --- | --- |
| [Stripe](#stripe) | Restricted (`rk_`) or secret (`sk_`) API key | Customers, subscriptions, invoices, payments and more |
| [WorkOS](#workos) | Secret API key (`sk_`) | Organizations, users, SSO and directories |
| [PostHog](#posthog) | Personal API key (`phx_`) | Persons, groups and events |
| [GitHub](#github) | Fine-grained (`github_pat_`) or classic (`ghp_`) token | Issues, pull requests, comments and reviews |
| [Linear](#linear) | Personal API key (`lin_api_`) | Teams, projects, cycles, issues and comments |
| [Cal.com](#cal-com) | API key (`cal_live_`) | Bookings, attendees, event types and schedules |
| [Granola](#granola) | API key (`grn_`) | Meeting notes and attendees, kept as documents too |
| [PostgreSQL](#postgresql) | Database user and password | The tables you choose |
| [MySQL](#mysql) | Database user and password | The tables you choose |
| [Amazon S3](#amazon-s3) | IAM role, or an access key | Parquet, JSON and CSV files as tables |
| [API source](/foundry/data/api-sources) | None: senders use send tokens | The pieces your apps and agents send |

## Stripe

In Stripe, open **API keys** and select **Create restricted key**. Name it "Helix
Foundry", set **Read** on the objects you want and leave everything else as **None**.
Foundry reads test or live data, as the key says. Use a sandbox or test mode key first
to try Foundry without live data.

Syncs `customers`, `products`, `prices`, `coupons`, `promotion_codes`, `subscriptions`,
`subscription_items`, `invoices`, `invoice_line_items`, `charges`, `payment_intents`,
`refunds`, `disputes`, `payouts` and `balance_transactions`. A table the key can't read
is skipped and named after the test; the test fails only when the key can read none.

Also give the key **Read** on **Events**. On Pro and Max, syncs then read only the
objects that changed; without it, every sync reads every object in full, and the test
warns you.

## WorkOS

In WorkOS, open **API Keys** in the environment you want to import (Staging or
Production) and copy the secret key. Production keys are shown only when created, so
create a new one if you no longer have it. WorkOS keys can make changes, but Foundry
only reads.

Syncs `organizations`, `users`, `organization_memberships`, `invitations`,
`sso_connections`, `directories`, `directory_users`, `directory_groups` and
`directory_group_members`.

## PostHog

In PostHog, open **Settings** → **Personal API keys** and select **Create personal API
key**. Give it the **Query** and **Project** read scopes only, limited to the project you
want to import.

| Field | Notes |
| --- | --- |
| Region | US Cloud, EU Cloud or Self-hosted (an HTTPS host). |
| Project ID | Optional when the key sees one project; Foundry fills it in after the test. |
| Event history (days) | 1 to 365, 30 by default. |

Syncs `persons`, `person_distinct_ids` and `groups` in full, and `events` and
`daily_event_counts` for the event history you chose.

</Frame>

## GitHub

In GitHub, open **Settings** → **Developer settings** → **Fine-grained tokens** and
create a token named "Helix Foundry". For an organization's repositories, choose the
organization as the resource owner; it may need to approve the token. Choose the
repositories to import, and set **Issues** and **Pull requests** to **Read-only**. A
classic token (`ghp_…`) with the `repo` scope works too.

| Field | Notes |
| --- | --- |
| Repositories | Optional: one `owner/name` per line. Blank syncs every repository the token can read, up to 100. |
| Review history (days) | 1 to 365: how far back pull request reviews are read. |

Syncs `repositories`, `users`, `labels`, `milestones`, `issues`, `pull_requests`,
`issue_comments` and `pull_request_reviews`. Foundry never reads code.

## Linear

In Linear, open **Settings** → **Security & access** and create a personal API key named
"Helix Foundry" with **Read** access. It reads every team you can see in Linear.

Syncs `teams`, `users`, `projects`, `cycles`, `workflow_states`, `issue_labels`,
`issues` and `comments`.

## Cal.com

In Cal.com, open **Settings** → **Developer** → **API keys** and create a key named
"Helix Foundry". Turn on **Never expires**, or choose a long expiry: syncs stop when the
key expires. Cal.com shows the key once. Cal.com keys can make changes, but Foundry only
reads. Only Cal.com's cloud is supported.

Syncs `users`, `teams`, `team_memberships`, `event_types`, `schedules`, `bookings`,
`booking_attendees` and `booking_hosts`. Teams come with a Teams plan, and only a team
admin's key reads the team's other members.

## Granola

API keys come with Granola Business and Enterprise. In the Granola desktop app, open
**Settings** → **Connectors** → **API keys** and select **Create new key**. Choose the
**Personal notes** scope, and **Public notes** too for notes shared with your team.

Syncs `notes`, with each note's summary, `note_attendees`, `note_folders`, `folders`
and `spaces`. Foundry also keeps each note's summary as a Markdown document, in a
**Notes** document set of the connection's own, which ontologies read like any other
[documents](/foundry/data/documents).

**Transcripts**, under the key, is off by default. Turn it on to keep each note's
transcript as a document too, in a **Transcripts** set beside Notes. Transcripts are
long: reading one into an ontology costs several times what a note does.

## PostgreSQL

Create a read-only user as an administrator, replacing the database name and password:

```sql
CREATE ROLE foundry_readonly LOGIN PASSWORD 'choose-a-password';
GRANT CONNECT ON DATABASE app TO foundry_readonly;
GRANT USAGE ON SCHEMA public TO foundry_readonly;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO foundry_readonly;
```

| Field | Default |
| --- | --- |
| Host, Database, Username, Password | Required. |
| Port | `5432` |
| Schema | `public` |
| Encryption (under **Connection options**) | Require TLS with certificate verification. Add a CA certificate for a private CA, or choose **No TLS**. |

After the test, choose the tables to sync. Every table in the schema starts selected,
and keeping them all also syncs tables added later; views are not synced. If a selected
table is dropped or renamed, syncs fail until you edit the connection and test it
again.

  <img src="https://assets.helix-db.com/docs/foundry/data/postgresql-form.png" alt="The PostgreSQL form with the read-only user SQL, the outbound addresses and the connection fields" />
</Frame>

## MySQL

The same fields as PostgreSQL, with port `3306` and no schema: Foundry reads the
database you name. Give the user `SELECT` on it only.

## Amazon S3

Foundry reads Parquet, JSON, JSON Lines and CSV files (plain, gzip, zstd or bzip2) from
one folder of a bucket. Files with the same shape become one table, named after their
folder or file name, and every sync reads them all again.

| Field | Notes |
| --- | --- |
| Bucket | Required. Pasting an `s3://bucket/folder/` address fills both fields. |
| Folder | Optional; the whole bucket without one. |
| Access | **IAM role** (recommended) or **Access key**. |
| Region (under **Advanced**) | Detected by the test. |
| Endpoint (under **Advanced**, access key only) | For S3-compatible storage such as Cloudflare R2, MinIO, Backblaze B2 or Wasabi. |

With an **IAM role**, Foundry assumes a role in your AWS account with the workspace's
external ID, which the form shows with a **Copy** button. In AWS IAM, create a role
with **Custom trust policy** and paste the trust policy the form shows, which requires
that ID. Then give the role the inline permissions policy the form shows, which lists
the folder and reads its files only, and paste the role's ARN. Foundry won't use a role
whose trust policy doesn't require the external ID, and checks this on every test and
sync with an ID that must fail, which your CloudTrail shows as a denied `AssumeRole`.

<Frame>
  <img src="https://assets.helix-db.com/docs/foundry/data/s3-form.png" alt="The Amazon S3 form with the bucket and folder, IAM role access chosen and the workspace's external ID" />
</Frame>

With an **access key**, create an IAM user with the same permissions policy and an
access key for it. Leave the secret blank when you edit the connection to keep the
stored one.

If the bucket uses a customer-managed KMS key, also allow `kms:Decrypt` on that key.
AWS bills your account for the requests and for data transferred out of the bucket's
region.

The test lists each table with its format, files, size, columns and key, a preview of
its rows, and any file Foundry can't read. Choose the tables to sync; the form adds up
their size, and a connection syncs at most 20 GB.

  <img src="https://assets.helix-db.com/docs/foundry/data/s3-tested.png" alt="A tested S3 folder with its customers, events and orders tables, Selected 1.2 GB of 20 GB, and two files Helix can't read" />
</Frame>

## Network access for databases

Foundry connects to a database over the internet from Helix's network, so the
database must accept connections from outside your network. If it only accepts known
addresses, allow the outbound addresses the form lists, and select **Copy** to copy
them.

Foundry refuses private, loopback and shared address ranges, and follows no
redirects.

## Limits

| Limit | Value |
| --- | --- |
| Rows per table | 2,000,000, and 2 GiB. A larger table fails the sync: for a database, leave it out; for PostHog, shorten the event history. |
| Size of an S3 connection's tables, per sync | 20 GB. Choose fewer tables, or a narrower folder. |
| Documents a connection keeps, per set | The newest 1,000 |
| Scheduled syncs | Free daily, Pro hourly, Max every 15 minutes |
| One sync attempt | 2 hours |
| Attempts per sync | 3 |
| Syncs running per connection | 1 |
