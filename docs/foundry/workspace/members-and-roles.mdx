Everyone in a workspace shares its data, documents, ontologies and plan, unless an owner
or admin [restricts them to some sources](/foundry/workspace/access). Foundry uses the
workspace's Helix Cloud members and roles, so someone you add in either place has access
in both.

## See the members

**Settings** → **Members** lists everyone in the workspace with their role and when they
joined.

<Frame>
  <img src="https://assets.helix-db.com/docs/foundry/workspace/members.png" alt="The Members tab listing an owner and a member" />
</Frame>

## Invite people

Owners and admins select **Invite people**, enter an email address and choose a role:

- **Member** sees everything in the workspace, unless they're given sources under
  [Access](/foundry/workspace/access): then they see only what those hold. A new member
  can't read what loads wrote until you [let them](#what-new-members-can-read).
- **Admin** also connects data, invites people and manages billing.

<Frame>
  <img src="https://assets.helix-db.com/docs/foundry/workspace/invite.png" alt="The Invite to Acme dialog with an email address and the Admin role chosen" />
</Frame>

The invitation arrives by email and is accepted through Helix. To make someone an owner,
change a role, remove someone or manage pending invitations, use the
[Helix dashboard](https://helix-db.com/login).

## What each role can do

| Action | Owner | Admin | Member |
| --- | :---: | :---: | :---: |
| See connections, documents, ontologies, versions, loads, the plan and usage | ✓ | ✓ | ✓ |
| Ask the Analyst, explore and read records | ✓ | ✓ | With **Query read** on the database's project, or what [their sources](/foundry/workspace/access) hold |
| Add, sync, edit and delete connections | ✓ | ✓ | |
| Create API sources, and make and revoke their send tokens | ✓ | ✓ | |
| Upload, move, rename and delete documents and sets | ✓ | ✓ | |
| Arrange the Connectors explorer for the workspace | ✓ | ✓ | |
| Create and delete ontologies | ✓ | ✓ | |
| Generate, edit versions, make them current, load and settle reviews | ✓ | ✓ | |
| Invite people | ✓ | ✓ | |
| Share sources with members, teams and agent keys | ✓ | ✓ | |
| Upgrade, switch, cancel and manage billing | ✓ | ✓ | |
| Choose where the workspace's AI runs, bring its own key, and allow People enrichment | ✓ | | |

Creating or deleting an ontology and loading also need write access to the database's
Helix project, which owners and admins have.

## What new members can read

A new member sees the workspace's connections, documents, ontologies, versions and
loads, but has no **Query read** on any Helix project. Until they get read access, pages
that read what loads wrote (the Analyst, the Explorer, Records, entity pages and a
document's text in an ontology) say **You don't have read access to this database** or
**You can't read this ontology's database**.

An owner or admin grants read access in one of two ways:

| Grant | Where | The member then reads |
| --- | --- | --- |
| **Query read** on the Helix project that holds the ontology's database | [Helix dashboard](https://helix-db.com/login), under the workspace's members | Every ontology on that project's databases, whole |
| Sources | Foundry, **Settings** → [Access](/foundry/workspace/access) | The part of each ontology those sources hold, and nothing else |

Owners and admins have **Query read** on every project.

An agent you connect through the [Helix MCP](/foundry/agents/helix-mcp) acts with your
role and rights: it can do only what the table allows you, and it never adds connections,
deletes anything, invites people or changes billing.
