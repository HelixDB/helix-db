This tutorial takes a new workspace from sign-in to a first answer and an explored
graph. You need a Helix account and some data: a source to read, such as a Stripe
account, or documents such as contracts. Owners and admins of a workspace can do every
step. Members can follow along read-only once an ontology exists; asking about a load
and exploring it also need **Query read** on its database's Helix project.

<Steps>
  <Step title="Sign in">
    Open [foundry.helix-db.com](https://foundry.helix-db.com) and continue with
    Google, GitHub or Microsoft, using the account you use for Helix Cloud.

    <Frame>
      <img src="https://assets.helix-db.com/docs/foundry/start-here/sign-in.png" alt="The Helix Foundry sign-in page with Google, GitHub and Microsoft buttons" />
    </Frame>
  </Step>

  <Step title="Choose a workspace">
    Foundry opens your workspace when you have one, or the workspace picker when you
    have several or none. Select **Create workspace** to start a new one; it starts on
    Foundry Free.

    <Frame>
      <img src="https://assets.helix-db.com/docs/foundry/start-here/create-workspace.png" alt="The Create a workspace dialog over the workspace picker" />
    </Frame>

    A workspace without an ontology opens on **Create your first ontology**, which
    takes you through the steps below. To hand them to your agent instead, select
    **Copy prompt** under **Set up with your agent**, and paste it into Claude Code,
    Codex or another agent with the [Helix MCP](/foundry/agents/helix-mcp).

    <Frame>
      <img src="https://assets.helix-db.com/docs/foundry/start-here/onboarding.png" alt="Create your first ontology for a new workspace, with Set up with your agent above its Name step" />
    </Frame>
  </Step>

  <Step title="Name it and choose its database">
    Name the ontology, then choose the Helix database its loads write into: one you have,
    or a new one on Helix's shared cluster.
  </Step>

  <Step title="Connect your data or upload documents">
    Choose what Foundry's agent drafts from. Select **Add data** to connect a source in
    place: choose it, follow its numbered steps to create a read-only credential, select
    **Test connection** to see what it can read, then **Connect and sync**. Its first
    sync shows in its row.

    <Frame>
      <img src="https://assets.helix-db.com/docs/foundry/data/stripe-tested.png" alt="The Stripe connection form after a successful test, listing the objects the key can read" />
    </Frame>

    Select **Upload documents** for files such as contracts, notes, CSV exports or PDFs.
    They go into the **General** document set, which is then chosen. Any of tables, API
    sources and documents will do; you need at least one.

    <Frame>
      <img src="https://assets.helix-db.com/docs/foundry/ontology/new-ontology-data.png" alt="The step Connect your data or upload documents, with the Stripe and Shop database connectors and the General document set chosen" />
    </Frame>

    See [Connect data](/foundry/data/connect-data) for every source, and
    [Documents](/foundry/data/documents) for what Foundry reads in each format.
  </Step>

  <Step title="Say what it should serve, and create it">
    Optionally, write the questions people will ask of it, in your words. Then select
    **Create and generate**: Foundry creates the ontology and its agent drafts a first
    version. The page follows the generation until it stores the version.

    <Frame>
      <img src="https://assets.helix-db.com/docs/foundry/ontology/new-ontology-review.png" alt="The New ontology page at its Review and create step, with the name, database, data, documents and goal chosen, and Create and generate" />
    </Frame>

    See [Create an ontology](/foundry/ontologies/create-an-ontology) for each step. Until
    the ontology is set up, its overview lists the steps left, so you can carry on from
    there at any time.
  </Step>

  <Step title="Review it and make it current">
    On the generation's page, select **Review version**. Read its types, links,
    mappings and rules, then select **Make current**. Earlier versions stay, so you can
    roll back at any time.

    <Frame>
      <img src="https://assets.helix-db.com/docs/foundry/ontology/version.png" alt="An agent-drafted version that reads General, with its Graph, Types, Links, Mappings, Sources, Rules, Questions, TOML and Edit tabs" />
    </Frame>
  </Step>

  <Step title="Load it">
    On the ontology's overview, select **Load data**. The dialog says which tables and
    document sets the load reads and what it may spend; select **Load**. When it
    finishes, it becomes the current load. From then on, Foundry
    [refreshes it](/foundry/ontologies/load-data#automatic-refreshes) when your synced
    data changes.

    <Frame>
      <img src="https://assets.helix-db.com/docs/foundry/ontology/load-dialog.png" alt="The Load version 3 into contracts dialog with the tables, the documents from General, spending and limits" />
    </Frame>
  </Step>

  <Step title="Ask a question">
    Select **Ask** in the sidebar; Foundry also opens on it. Write a question or pick a
    suggestion, and select the arrow. The answer cites the records, rows and quotes it
    came from, and the thread stays in the sidebar.

    <Frame>
      <img src="https://assets.helix-db.com/docs/foundry/ask/thread.png" alt="An Ask thread with its steps and an answer citing its sources, and the threads in the sidebar" />
    </Frame>
  </Step>

  <Step title="Explore it">
    Select **Explorer**. The graph opens on a connected sample of the load. Search
    with <kbd>/</kbd>, double-click a node to expand it, or switch to **Records** to read
    each type as a table.

    <Frame>
      <img src="https://assets.helix-db.com/docs/foundry/explore/explorer-node.png" alt="The Explorer with a customer selected and its properties and relationships in the inspector" />
    </Frame>
  </Step>
</Steps>
