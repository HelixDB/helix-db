<div className="flex flex-wrap gap-2"><Badge color="green" size="sm">Tutorial</Badge></div>

This tutorial takes a new workspace from sign-in to a first answer and an explored
graph. You need a Helix account and some data: a source to read, such as a Stripe
account or a PostgreSQL database, or documents such as contracts. To see Foundry work
before you connect anything, try the [sample company](/foundry/start-here/sample-company)
first. Owners and admins can do every step.

<Frame caption="The path end to end: synced data, a generated draft, a load, the Explorer and the Analyst.">
  <video controls muted playsInline preload="none" poster="https://assets.helix-db.com/docs/foundry/start-here/tour-poster.png" className="w-full" src="https://assets.helix-db.com/docs/foundry/start-here/tour.webm"></video>
</Frame>

<Steps>
  <Step title="Sign in">
    Open [foundry.helix-db.com](https://foundry.helix-db.com) and continue with
    Google, GitHub or Microsoft, using the account you use for Helix Cloud.

    <Frame>
      <img src="https://assets.helix-db.com/docs/foundry/start-here/sign-in.png" alt="The Helix Foundry sign-in page with Google, GitHub and Microsoft buttons" />
    </Frame>
  </Step>

  <Step title="Choose a workspace">
    Foundry opens your workspace when you have one, or the workspace picker when you
    have several or none. Select **Create workspace** to start a new one; it starts on
    Foundry Free.

    <Frame>
      <img src="https://assets.helix-db.com/docs/foundry/start-here/create-workspace.png" alt="The Create a workspace dialog over the workspace picker" />
    </Frame>
  </Step>

  <Step title="Choose how to start">
    A workspace without an ontology opens on **Get started**. It offers:

    - **Start with a sample company**: **See it on a sample company (1 min)** builds an
      ontology from a made-up company's data and answers a question about it. See
      [Try the sample company](/foundry/start-here/sample-company).
    - **Or start with your own**, with a toggle:
      - **Set up with your agent**, the default: **Copy prompt** copies a prompt for
        Claude Code, Codex or another agent with the
        [Helix MCP](/foundry/agents/helix-mcp#set-up-a-workspace-with-your-agent),
        which then does the steps below with you.
      - **Use my own data**: select **Continue** to do the steps below yourself.

    <Frame>
      <img src="https://assets.helix-db.com/docs/foundry/start-here/onboarding.png" alt="Get started: the Start with a sample company card, then Or start with your own with the Set up with your agent and Use my own data toggle" />
    </Frame>

    The rest of this tutorial follows **Use my own data**. The page that opens, **Your
    first ontology**, has three steps.
  </Step>

  <Step title="Connect your data or upload documents">
    Choose what Foundry's agent drafts from. Select **Add data** to connect a source in
    place: choose it, follow its numbered steps to create a read-only credential, select
    **Test connection** to see what it can read, then **Connect and sync**. Its first
    sync shows in its row.

    <Frame>
      <img src="https://assets.helix-db.com/docs/foundry/data/stripe-tested.png" alt="The Stripe connection form after a successful test, listing the objects the key can read" />
    </Frame>

    Select **Upload documents** for files such as contracts, notes, CSV exports or PDFs.
    They go into the **General** document set, which is then chosen. Any of tables, API
    sources and documents will do; you need at least one. Select **Continue**.

    <Frame>
      <img src="https://assets.helix-db.com/docs/foundry/ontology/new-ontology-data.png" alt="The step Connect your data or upload documents, with the Stripe and Shop database connectors and the General document set chosen" />
    </Frame>

    See [Connect data](/foundry/data/connect-data) for every source, and
    [Documents](/foundry/data/documents) for what Foundry reads in each format.
  </Step>

  <Step title="Describe what you want to understand">
    Optionally, under **What do you want to understand?**, write the questions you want
    to answer, in your words. Select **Continue**, or **Skip** to leave it empty.
  </Step>

  <Step title="Create it">
    The last step says what happens next; select **Create and generate**. Foundry:

    1. names the ontology after what it drafts from, such as "Stripe and Contracts";
    2. creates a new Helix database for it, named the same, in the workspace's first
       Helix project, or in a new project named after the workspace;
    3. has its agent draft a first version;
    4. makes that draft current and loads it into the database as soon as it's ready;
    5. emails you when you can ask it questions.

    The generation's page opens and follows the draft. You can leave it: the draft and
    the load carry on, and the email links to the ontology. If the draft or its load
    fails, the email says why, with a link to try again.

    <Frame>
      <img src="https://assets.helix-db.com/docs/foundry/ontology/new-ontology-review.png" alt="Your first ontology at its Review and create step, saying Foundry creates the ontology on a new Helix database, drafts it, makes it current, loads it and emails you, with Create and generate" />
    </Frame>

    <Note>
      The new database uses the workspace's Helix Cloud plan. A workspace created in
      Foundry gets one free; see
      [Plans and billing](/foundry/workspace/plans-and-billing#the-helix-cloud-plan-for-databases).
    </Note>
  </Step>

  <Step title="Ask the Analyst a question">
    Once the load is ready, select **Analyst** in the sidebar; Foundry also opens on it.
    Write a question or pick a suggestion, and select the arrow. The answer cites the
    records, rows and quotes it came from, and the thread stays in the sidebar.

    <Frame>
      <img src="https://assets.helix-db.com/docs/foundry/ask/thread.png" alt="An Analyst thread with its steps and an answer citing its sources, and the threads in the sidebar" />
    </Frame>
  </Step>

  <Step title="Explore it">
    Select **Explorer**. The graph opens on a connected sample of the load. Search
    with <kbd>/</kbd>, double-click a node to expand it, or switch to **Records** to read
    each type as a table.

    <Frame>
      <img src="https://assets.helix-db.com/docs/foundry/explore/explorer-node.png" alt="The Explorer with a customer selected and its properties and relationships in the inspector" />
    </Frame>
  </Step>
</Steps>

Your first ontology's draft was made current without a review. To see what it holds,
open it under **Ontologies**: its overview shows its types and links. To change it,
[generate](/foundry/ontologies/generate-and-version#generate-a-draft) or
[edit](/foundry/ontologies/generate-and-version#edit-a-version) a new version; you
review every later version before you make it current.

Members can follow along read-only once an ontology exists. Asking and exploring also
need **Query read** on the database's Helix project, or sources shared with them; see
[Members and roles](/foundry/workspace/members-and-roles#what-new-members-can-read).
