A load writes the ontology's current version into its Helix database: your synced
tables as its mappings shape them, then your documents. Each load is a complete copy,
written beside the earlier ones, so you can compare them and switch back. Reads go to
the current load.

## Start a load

You can load when the current version is an agent draft that finished. Select **Load
data** on the overview or in **Data loads**. The dialog says what the load reads and
what it may spend; select **Load** to start it.

<Frame>
  <img src="/images/foundry/ontology/load-dialog.png" alt="The Load version 3 into contracts dialog listing tables, documents, spending and limits" />
</Frame>

## Follow a load

The load's page follows each step: preparing, writing the tables, reading the
documents, finishing. A load is **Writing**, then **Ready**. It ends **Partial** when
it reached the spending cap with its tables written but some documents unread, or
**Failed**.

<Frame>
  <img src="/images/foundry/ontology/load.png" alt="A ready, current load of version 3 with its summary and Open Explorer" />
</Frame>

The newest load that finishes **Ready** becomes current. A **Partial** load becomes
current only when the ontology has no current load.

- If a source synced again while the load ran, the load says so and offers a new one.
- If the database is new and still starting, the load waits and tries again by itself.
- An ontology runs one load at a time.

## Manage loads

**Data loads** lists the loads kept: the current one and the newest others, five in
all. Older loads are deleted from the database in the background. Each row shows the
load's version, status, node and fact counts, and its jobs.

<Frame>
  <img src="/images/foundry/ontology/loads.png" alt="Data loads listing two ready loads of version 3, one current" />
</Frame>

| Action | Does |
| --- | --- |
| **Open** | The load's page, with its steps and spend |
| **Compare with current** | The Explorer with the load and the current one side by side |
| **Set current** | Makes a Ready or Partial load the one every page reads |
| **Delete** | Removes what the load wrote, with the links others added to its nodes. Never the current load or one still writing. |
| **Retry delete** | Tries a delete that failed again |

## Spending and limits

Reading documents uses models, so it costs money; tables don't. Reading the same text
with the same models again costs nothing.

| Limit | Value |
| --- | --- |
| Per load | $20 |
| Per workspace, per month | $100 |
| Documents | 200 in the workspace, 256 KiB each |
| Loads kept per ontology | 5 |

A load that reaches the cap stops, and the documents it didn't reach wait for the next
one.
