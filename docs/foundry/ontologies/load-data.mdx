A load writes the ontology's current version into its Helix database: your synced
tables as its mappings shape them, then the documents of the sets the version reads.
Each load is a complete copy, written beside the earlier ones, so you can compare them
and switch back. Reads go to the current load.

## Start a load

You can load when the current version is an agent draft that finished. Select **Load
data** on the overview, on the version's page or in **Data loads**. The dialog says
what the load reads and what it may spend; select **Load** to start it.

- **Tables**: the synced tables the version's mappings read.
- **Documents**: the [document sets](/foundry/data/documents) the version reads, the
  ones its generation picked, and how many documents they hold. A set no route reads is
  stored, not read, and so are documents in formats ontologies don't read yet (anything
  but Markdown and text). Documents added to these sets later are read as they arrive.

<Frame>
  <img src="https://assets.helix-db.com/docs/foundry/ontology/load-dialog.png" alt="The Load version 3 into contracts dialog: two Stripe tables, one document from General, the spending caps and the limits" />
</Frame>

The version's page shows the same sets in its header, as **Reads …**. To read another
set, generate a version that picks it, or
[edit the version](/foundry/ontologies/generate-and-version#edit-a-version) to route it,
then load that version.

## Follow a load

The load's page follows each step: preparing, writing the tables, reading the
documents, finishing. A load is **Writing**, then **Ready**. It ends **Partial** when
it reached the spending cap with its tables written but some documents unread, or
**Failed**.

<Frame>
  <img src="https://assets.helix-db.com/docs/foundry/ontology/load.png" alt="A ready, current load of version 3 with its summary, Review documents, Rule breaks and Open Explorer" />
</Frame>

When the load leaves items to review, **Review documents** opens the ontology's
documents that need review. **Rule breaks** lists the records that break the version's
constraints.

The newest load that finishes **Ready** becomes current. A **Partial** load becomes
current only when the ontology has no current load.

- If a source synced again while the load ran, the load says so and offers a new one.
- If the database is new and still starting, the load waits and tries again by itself.
- An ontology runs one load at a time.

Loading, setting a load current and deleting one need owner or admin rights and write
access to the database's Helix project.

## Manage loads

**Data loads**, among the ontology's pages in the Ontologies panel, lists the loads
kept: the current one and the newest others, five in all. Older loads are deleted from
the database in the background. Each row shows the load's version, status, node and
fact counts, and its jobs. Select a row to open the load's page, with its steps and
spend.

<Frame>
  <img src="https://assets.helix-db.com/docs/foundry/ontology/loads.png" alt="Data loads listing two ready loads of version 3, one current, each with Open and a menu of more actions" />
</Frame>

**Open** reads the load in the Explorer. The **⋯** menu beside it holds the rest:

| Action | Does |
| --- | --- |
| **Compare with current** | The Explorer with the load and the current one side by side |
| **Set current** | Makes a Ready or Partial load the one every page reads |
| **Delete** | Removes what the load wrote, including links your own data added to its nodes. Never the current load or one still writing. |
| **Retry delete** | Tries a delete that failed again |

## Spending and limits

Reading documents uses models, so it costs money; tables don't. Reading the same text
with the same models again costs nothing.

| Limit | Value |
| --- | --- |
| Per load | $20 |
| Per workspace, per month | $100 |
| Documents | 200 in the workspace, 1 MiB each |
| Loads kept per ontology | 5 |

A load that reaches its cap stops **Partial**. The documents it didn't reach are read
into it once it's current and the month has budget left; a new load reads every
document again. Once the workspace has spent $100 in a month, Foundry refuses new loads
until the next month, and new uploads aren't read.
