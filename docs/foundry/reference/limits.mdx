The limits Foundry applies, by area. Each guide explains what happens when you reach one.

## Connections

| Limit | Value |
| --- | --- |
| Scheduled syncs | Free once a day, Pro every hour, Max every 15 minutes; PostHog once a day on every plan |
| Rows per table | 2,000,000, and 2 GiB |
| One sync attempt | 2 hours |
| Attempts per sync | 3 |
| Syncs running per connection | 1 |
| Size of an S3 connection's tables, per sync | 20 GiB |
| PostHog event history | 1 to 365 days, 30 by default |
| GitHub review history | 1 to 365 days, 90 by default |
| GitHub repositories | 100 at most; with none named, a token or app install that reads more than 100 is refused until you list them |
| Slack history | 1 to 365 days, 90 by default |
| Google Workspace past events | 1 to 365 days, 90 by default, and 30 days ahead |
| Documents a connection keeps, per set | The newest 1,000 |
| Your folders in the Connectors explorer | 50, at the root, holding connections only |
| Folder name | 120 characters |

## API sources

| Limit | Value |
| --- | --- |
| API sources per workspace | 20 |
| Live send tokens per source | 10 |
| Pieces per send | 500, with at most 1 MiB of data together |
| Request body over HTTP | 2 MiB, arriving within 15 seconds |
| Piece | 256 KiB of data, 64 levels deep; an id of 1 to 128 printable ASCII characters, no spaces; field names up to 64 bytes |
| Fields per source | 200 |
| Sends per source | 5 a second, in bursts of up to 20 |
| Sends per workspace | 20 a second, in bursts of up to 50 |
| Per workspace, per UTC day | 200,000 pieces and 1 GiB of data |
| Rows per source | 2,000,000, and 2 GiB |
| Sync after a send | About a minute |
| Time between a source's syncs | At least 1 minute, plus 10 minutes per million rows of its table |
| Pieces read by entity extraction | The newest 500 |
| Extraction no person started | $5 a month per source, $20 a month per workspace |
| Recall | 50 notes a call, 20 by default, with at most 64 KiB of text; a query of 10 words and 200 bytes; a source whose table is at most 64 MiB |

## Documents

| Limit | Value |
| --- | --- |
| File types | `.md`, `.markdown`, `.mdx`, `.txt`, `.vtt`, `.pdf`, `.csv`, `.tsv`, `.json`, `.jsonl`, `.ndjson`, `.parquet` |
| Formats ontologies read | All of them: text and PDFs for names and facts, table files as tables |
| Markdown, MDX, text and WebVTT | 1 byte to 1 MiB |
| PDF | 3 MiB and 150 pages; its text at most 1 MiB. Scanned PDFs have no text to read. |
| CSV, TSV, JSON, JSONL and Parquet | 3 MiB; up to 1,000 columns and 1 MiB per row or line |
| Uploaded documents per workspace | 200; connections' documents don't count |
| Name | 255 characters, no slash, backslash or control character |
| Document sets per workspace | 20 |
| Set name | 120 characters, unique in the workspace ignoring case and accents |
| Set description | 1,000 characters |

## Generations

| Limit | Value |
| --- | --- |
| Goal | 2,000 characters |
| Tables per generation | 50: synced tables, table files and API sources read through structured mappings together |
| Document sets per generation | 20; each API source read by entity extraction counts as one |
| Documents the agent reads | Up to 5 of the newest in each set |
| Attempts per generation | 3 |
| Spend per attempt | $5 |
| Monthly spend cap | None; not shown in [Usage](/foundry/workspace/usage#generations) |
| Generations running per ontology | 1 |
| Generations per workspace | 10 an hour; version edits don't count |

## Loads

| Limit | Value |
| --- | --- |
| Document reading spend, per load | $10 |
| Document reading spend, per workspace each month | $50, of which work no person started may spend $40 |
| Automatic refreshes | At most once per the plan's sync interval |
| Loads kept per ontology | 5: the current one and the four newest others |
| Loads or extracts running per ontology | 1 |

## Questions

[Questions](/foundry/ask/ask-questions) Founder asks for you, and those asked through the Helix MCP's `helix_foundry_ask`.

| Limit | Value |
| --- | --- |
| Per question | $0.50, 20 steps and 4 minutes |
| Question | 4,000 characters |
| Questions running per workspace | 2 |
| Questions per workspace, per hour | 30 |
| Spend per workspace, per month | $15, apart from loads'; a question is refused once less than $0.50 is left |
| Questions per member or agent key reading through [sources](/foundry/workspace/access), per hour | 10 |
| Spend per member or agent key reading through sources, per month | $10 |

## Founder

[Founder](/foundry/ask/founder)'s own turns, apart from the questions it asks.

| Limit | Value |
| --- | --- |
| Per turn | $0.50, 20 steps and 4 minutes |
| Message | 4,000 characters |
| Messages per person, per hour | 30 |
| Turns running per workspace | 2 |
| Spend per workspace, per month | $30, apart from questions' |
| Prepared actions waiting per thread | 3 |

## Use cases

Your agents' [use case runs](/foundry/agents/helix-mcp#use-cases), assessed on each ontology's **Usage** page.

| Limit | Value |
| --- | --- |
| Run assessments, spend per workspace, per month | $20; a run that finishes once the month's spend is within $1 of it isn't assessed |

## Workflows

See [Workflows](/foundry/automate/workflows).

| Limit | Value |
| --- | --- |
| Workflows per workspace | 50 |
| Runs per workspace | 200 in any 24 hours; past that, a trigger's run is skipped and **Run now** is refused |
| Founder steps' spend per workspace, per month | $20, at most $0.50 a step, 2 running at once |
| Steps per workflow | 50, its trigger included |
| Failed runs in a row before a workflow pauses | 3 |

## Dashboards

See [Dashboards](/foundry/automate/dashboards).

| Limit | Value |
| --- | --- |
| Dashboards per workspace | 200 |
| Pinned in the sidebar, per workspace | 20 |
| Tiles per dashboard | 20, up to 3 a row |
| Name | 120 characters |
| Description | 1,000 characters |
| Tile title | 80 characters |

## Helix MCP

| Limit | Value |
| --- | --- |
| A confirmation for a change | One use, within 5 minutes |
| Graph reads per call | 1 to 20 |
| `helix_foundry_ask` waits for an answer | 25 seconds; longer questions carry on |
| Feedback | 20 an hour per caller, 4,096 bytes each |

## Explorer and Records

| Limit | Value |
| --- | --- |
| First view of a load | A connected sample of about 320 records |
| Records per page | 50 |
| Records reachable by paging, per type | 10,000 |
| Matches counted by a search or filter | 1,000 |
| Records compared per type, per side | 5,000 |

## Ontologies

| Limit | Value |
| --- | --- |
| Ontologies per database | 1 |
| Databases per ontology | 1 |
