Every deployment option runs the same queries with the same SDKs, so you can develop
against one and deploy to another without changing application code. Choose based on
where the engine runs, where data is stored, and who operates it.

| Mode | Best for | Interface | Storage | Availability |
| --- | --- | --- | --- | --- |
| Helix Cloud | Production services with managed operations | HTTPS | Managed object storage | Highly available |
| Local server | Development, production-shaped testing, and self-hosting on a trusted network | HTTP, without authentication or TLS | Memory, a local directory, or S3-compatible storage | Single node |
| Embedded | In-process applications and local tools | Native SDK call | Memory, disk, or object storage | In process |

## Helix Cloud

Helix Cloud runs a highly available cluster that provides managed deployment, storage,
database authentication, and read scaling. It supports multi-tenant and single-tenant
deployments; BYOC is coming soon.

## Local server

The local server runs the standalone HelixDB container on your own machine or
infrastructure. It exposes the same `POST /v2/query` interface as Helix Cloud, which
makes it the default development target: the same queries run unchanged in Cloud.
Only the client configuration changes, because Cloud requires an API key and a
database ID, or a database-specific endpoint URL.

<Warning>
The local server has no authentication and no TLS, and `helix start` publishes its
port on every network interface of the host. Anyone who can reach that port can read
and write every record. Self-host it only on a trusted network, behind a proxy that
terminates TLS and authenticates requests. See [Local server](/database/helix-db/start-here/local-development/local-server#secure-the-server).
</Warning>

## Embedded

Embedded clients open the engine inside your process and skip HTTP entirely.
TypeScript and Python ship embedded runtime packages. Rust embeds the engine through
the `embedded` feature, which the crates.io release does not include, so add the crate
as a git dependency. The Go SDK has no embedded runtime: its embedded constructors
return `ErrNativeBindingsUnavailable`.

## Which should I use?

- **Building a networked application?** Develop against the local server.
- **Going to production?** Use Helix Cloud for managed operations and high
  availability.
- **Shipping a tool or app that owns its data?** Use embedded mode when process-local
  execution simplifies your architecture and the SDK's native packaging fits how you
  distribute.
