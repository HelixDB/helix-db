Traversal operations consume the current stream and produce the next stream.

| Operation | Result |
| --- | --- |
| `out(label)` | Destination nodes of outgoing edges |
| `in(label)` | Source nodes of incoming edges |
| `both(label)` | Adjacent nodes in either direction |
| `outE(label)` / `inE(label)` | The edges themselves |
| `outN()` / `inN()` | Move from an edge to its endpoint |
| `dedup()` | Remove duplicate results |

## Follow a named result

<CodeGroup>

```rust Rust
read_batch()
    .var_as(
        "user",
        g().n_where(SourcePredicate::eq("username", "alice")),
    )
    .var_as(
        "friends",
        g()
            .n(NodeRef::var("user"))
            .out(Some("FOLLOWS"))
            .dedup()
            .limit(25)
            .value_map(Some(vec!["$id", "username"])),
    )
    .returning(["friends"]);
```

## Preserve correlated values

A traversal normally forgets where it has been: after `out(...)`, each row holds only
the node it reached. Use `bind` to name a point in the traversal so each result row
keeps a value from it. This request returns one row per service and the workload it
routes to:

<CodeGroup>

```rust Rust
read_batch()
    .var_as(
        "routes",
        g()
            .n_with_label("Service")
            .bind("service")
            .out(Some("ROUTES_TO"))
            .project_bindings(vec![
                BindingProjection::binding("service", "name", "service"),
                BindingProjection::current("name", "workload"),
            ]),
    )
    .returning(["routes"]);
```

```ts TypeScript
readBatch()
  .varAs(
    "routes",
    g()
      .nWithLabel("Service")
      .bind("service")
      .out("ROUTES_TO")
      .projectBindings([
        BindingProjection.binding("service", "name", "service"),
        BindingProjection.current("name", "workload"),
      ]),
  )
  .returning(["routes"]);
```

```go Go
helix.ReadQuery("service_routes").
	VarAs(
		"routes",
		helix.G().
			NWithLabel("Service").
			Bind("service").
			Out("ROUTES_TO").
			ProjectBindings(
				helix.ProjectNamedBinding("service", "name", "service"),
				helix.ProjectCurrentBinding("name", "workload"),
			),
	).
	Returning("routes")
```

Bindings are row-local, so each row pairs a workload with the service that reached it
rather than joining unrelated paths. Branches can bind optional values and coalesce
them during projection; see [Project correlated bindings](/database/helix-db/query-guides/projections#project-correlated-bindings).

## Avoid accidental path growth

- Filter as close to the source as possible.
- Use a label on relationship steps when the schema provides one.
- Add `dedup()` when multiple paths can reach the same entity.
- Bound recursive traversal with a maximum depth.
- Project only the fields needed by the caller.
