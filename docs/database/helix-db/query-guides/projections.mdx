Projection operations turn a traversal stream into the response shape your application
needs. They are terminal: no step can follow a projection.

## Choose a projection

| Intent | Operation |
| --- | --- |
| Selected fields | `valueMap` / `value_map` (`ValueMapAll` in Go for every field) |
| Renamed or computed fields | `project` |
| Correlated row fields | `projectBindings` / `project_bindings` |
| Present fields only, dropping rows that have none | `values` |
| IDs or labels | `id`, `label` |
| Edge properties with endpoints | `edgeProperties` / `edge_properties` |
| Count or existence | `count`, `exists` |
| Groups | `group`, `groupCount` / `group_count` |
| Sum, minimum, maximum, mean | `aggregateBy` / `aggregate_by` with `AggregateFunction` |

## Field rules

| Virtual field | Exists on |
| --- | --- |
| `$id`, `$label` | Every node and edge |
| `$from`, `$to` | Edges: the source and target node IDs. `$from.name` or `$to.name` reads an endpoint property; in `project`, build those with `Projection.fromEndpoint` and `Projection.toEndpoint` (`ProjectFromEndpoint`, `ProjectToEndpoint` in Go). |
| `$distance`, `$score` | Search hits, until the traversal moves to another element |

- `valueMap` with no list returns every stored property plus `$id` and `$label`, never
  `$from`, `$to`, `$distance`, or `$score`; list those to return them.
- `valueMap([...])` returns the listed keys that are present; a row with none returns `{}`.
- `values([...])` is the same, but drops rows with none of the keys.
- `project` omits a property the row does not have. An expression that reads a missing
  property sees `null`.

## Computed fields

Pass expression projections to `project` to compute fields. This request returns each
line item's `sku` and `price` times `quantity`:

<CodeGroup>

```rust Rust
g().n_with_label("LineItem").project(vec![
    Projection::property("sku", "sku"),
    Projection::expr("total", Expr::prop("price").mul(Expr::prop("quantity"))),
])
```

```ts TypeScript
g().nWithLabel("LineItem").project([
  PropertyProjection.new("sku"),
  ExprProjection.new("total", Expr.prop("price").mul(Expr.prop("quantity"))),
])
```

```go Go
helix.G().NWithLabel("LineItem").Project(
	helix.ProjectProp("sku"),
	helix.ProjectExpr("total", helix.ExprProp("price").Mul(helix.ExprProp("quantity"))),
)
```

```python Python
g().n_with_label("LineItem").project([
    PropertyProjection.new("sku"),
    ExprProjection.new("total", Expr.prop("price").mul(Expr.prop("quantity"))),
])
```

```json JSON
{
  "request_type": "read",
  "query_name": "line_item_totals",
  "query": {
    "read": {
      "entries": [{
        "query": {
          "name": "items",
          "root": {
            "project": {
              "input": {
                "nodes_where": {
                  "predicate": {
                    "eq": {
                      "left": { "property": "$label" },
                      "right": { "constant": { "string": "LineItem" } }
                    }
                  }
                }
              },
              "projections": [
                { "property": { "source": "sku", "alias": "sku" } },
                {
                  "expr": {
                    "alias": "total",
                    "expr": {
                      "mul": {
                        "left": { "property": "price" },
                        "right": { "property": "quantity" }
                      }
                    }
                  }
                }
              ]
            }
          }
        }
      }],
      "returns": ["items"]
    }
  }
}
```

</CodeGroup>

Expressions read a property (`Expr.prop`), a literal (`Expr.val`), a parameter
(`Expr.param`), the element ID (`Expr.id`), or the current time (`Expr.timestamp` in
epoch milliseconds). They combine with `add`, `sub`, `mul`, `div`, `modulo` (`Mod` in
Go), and `neg`. `Expr.case` picks the first branch whose predicate matches, or `null`
without an else branch.

- `add`, `sub`, `mul`, and `div` always return an `f64`, so `1 + 2` returns `3.0`.
- A missing, `null`, or non-numeric operand fails the whole query with `invalid_query`.
  Filter those rows out first, for example with `isNotNull`.
- `modulo` takes integers only and fails on a zero divisor.

## Project correlated bindings

`projectBindings` / `project_bindings` emits one row per traversal result, reading
values from names captured earlier with [`bind`](/database/helix-db/query-guides/traversals#preserve-correlated-values).
`projectDistinctBindings` / `project_distinct_bindings` also removes duplicate
projected tuples.

When alternative branches bind different names, a row carries only the bindings its
own path set. Use `coalesce` to take the first binding that is present. This request
maps each service to a workload ID, whichever branch found it:

<CodeGroup>

```rust Rust [expandable]
read_batch()
    .var_as(
        "workloads",
        g().n_with_label("Service")
            .bind("service")
            .out(Some("ROUTES_TO"))
            .bind("pod")
            .optional(sub().in_(Some("CREATES")).bind("deployment"))
            .union(vec![
                sub().in_(Some("MANAGES")).bind("owner"),
                sub().out(Some("ROUTES_TO")).bind("workload"),
            ])
            .project_distinct_bindings(vec![
                BindingProjection::binding("service", "$id", "service_id"),
                BindingProjection::coalesce(
                    vec![
                        BindingValueRef::binding("deployment", "$id"),
                        BindingValueRef::binding("owner", "$id"),
                        BindingValueRef::binding("workload", "$id"),
                    ],
                    "workload_id",
                ),
            ]),
    )
    .returning(["workloads"]);
```

```ts TypeScript [expandable]
readBatch()
  .varAs(
    "workloads",
    g()
      .nWithLabel("Service")
      .bind("service")

      .union([sub().in("MANAGES").bind("owner"), sub().out("ROUTES_TO").bind("workload")])
      .projectDistinctBindings([
        BindingProjection.binding("service", "$id", "service_id"),
        BindingProjection.coalesce(
          [
            BindingProjection.bindingRef("deployment", "$id"),
            BindingProjection.bindingRef("owner", "$id"),
            BindingProjection.bindingRef("workload", "$id"),

      ]),
  )
  .returning(["workloads"]);
```

```cypher Cypher
MATCH (service:Service)-[:ROUTES_TO]->(pod)
OPTIONAL MATCH (deployment)-[:CREATES]->(pod)
WITH service, deployment, coalesce(deployment, pod) AS current
UNWIND ['MANAGES', 'ROUTES_TO'] AS branch
OPTIONAL MATCH (owner)-[:MANAGES]->(current) WHERE branch = 'MANAGES'
OPTIONAL MATCH (current)-[:ROUTES_TO]->(workload) WHERE branch = 'ROUTES_TO'
WITH service, deployment, owner, workload
WHERE owner IS NOT NULL OR workload IS NOT NULL
RETURN DISTINCT id(service) AS service_id, id(coalesce(deployment, owner, workload)) AS workload_id
```

</CodeGroup>

Cypher has no `UNION` (see the
[Cypher guide](/database/helix-db/query-guides/cypher#what-is-not-supported)), so the
Cypher tab gives each `union` branch its own row through `UNWIND`, runs that branch as
an `OPTIONAL MATCH`, and drops rows where the branch found nothing.

## Keep search scores after traversing

`$distance` and `$score` are gone once the traversal leaves the hit, and a projection
cannot run first because it ends the traversal. Bind the hit and read the score from the
binding. This request returns the ten closest documents with distance and author:

<CodeGroup>

```rust Rust
read_batch()
    .var_as(
        "hits",
        g().vector_search_nodes("Doc", "embedding", vec![0.1, 0.8, 0.2], 10, None)
            .bind("doc")
            .out(Some("AUTHORED_BY"))
            .project_bindings(vec![
                BindingProjection::binding("doc", "$id", "doc_id"),
                BindingProjection::binding("doc", "$distance", "distance"),
                BindingProjection::current("name", "author"),
            ]),
    )
    .returning(["hits"]);
```

```ts TypeScript
readBatch()
  .varAs(
    "hits",
    g()
      .vectorSearchNodes("Doc", "embedding", [0.1, 0.8, 0.2], 10, null)
      .bind("doc")
      .out("AUTHORED_BY")
      .projectBindings([
        BindingProjection.binding("doc", "$id", "doc_id"),
        BindingProjection.binding("doc", "$distance", "distance"),
        BindingProjection.current("name", "author"),
      ]),
  )
  .returning(["hits"]);
```

```go Go
helix.ReadQuery("docs_with_authors").
	VarAs(
		"hits",
		helix.G().
			VectorSearchNodes("Doc", "embedding", []float32{0.1, 0.8, 0.2}, 10).
			Bind("doc").
			Out("AUTHORED_BY").
			ProjectBindings(
				helix.ProjectNamedBinding("doc", "$id", "doc_id"),
				helix.ProjectNamedBinding("doc", "$distance", "distance"),
				helix.ProjectCurrentBinding("name", "author"),

	).
	Returning("hits")
```

The same pattern keeps `$score` from a text search.

Each row pairs one hit with one author, so a document with no `AUTHORED_BY` edge
produces no row. To keep it, bind the author in an optional step,
`optional(sub().out("AUTHORED_BY").bind("author"))`, and project
`BindingProjection.binding("author", "name", "author")`; the document then comes back
without an `author` field. Do not use `current` here: with no author, the current
element is still the document, so `current("name", ...)` returns the document's `name`.

## Aggregate

Aggregates run inside the transaction. This request counts orders per status and sums
their totals:

<CodeGroup>

```rust Rust
read_batch()
    .var_as("by_status", g().n_with_label("Order").group_count("status"))
    .var_as(
        "revenue",
        g().n_with_label("Order").aggregate_by(AggregateFunction::Sum, "total"),
    )
    .returning(["by_status", "revenue"]);
```

```ts TypeScript
readBatch()
  .varAs("by_status", g().nWithLabel("Order").groupCount("status"))
  .varAs("revenue", g().nWithLabel("Order").aggregateBy(AggregateFunction.Sum, "total"))
  .returning(["by_status", "revenue"]);
```


The response holds `"by_status": [{"status": "paid", "count": 12}, {"status": "refunded", "count": 2}]`
and `"revenue": [{"total_Sum": 1840.5}]`.

| Terminal | Returns | On an empty stream |
| --- | --- | --- |
| `count()` | A number | `0` |
| `exists()` | `true` or `false` | `false` |
| `id()`, `label()` | A list of IDs or labels | `[]` |
| `group(property)` | One object per value: the property, `count`, and `ids` | `[]` |
| `groupCount(property)` | One object per value: the property and `count` | `[]` |
| `aggregateBy(function, property)` | One object keyed by property and function, such as `total_Sum` or `score_Mean`, with an `f64` value | `0.0` for every function |

- Groups come back sorted by value. Rows without the property form a `null` group.
- `aggregateBy` reads `i64`, `f64`, and `f32` values and numeric strings, and skips
  everything else, so `AggregateFunction.Count` counts numeric values, not rows. Use
  `count()` to count rows.
- `Min` and `Max` with no numeric values return `0.0`, like a real zero. Check `count()`
  when that matters.

## Keep responses small

- Project only fields the caller uses.
- Bind a search hit before traversing away from it if the response needs its score; see
  [Keep search scores after traversing](#keep-search-scores-after-traversing).
- Use aggregates in the engine instead of returning full rows for client-side counting.
- Add `distinct` only when duplicate elimination is semantically required.
