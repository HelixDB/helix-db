A vector index ranks node or edge embeddings by distance to a query vector. Use it for
semantic search, recommendations, and retrieval over any label that stores an
embedding as a top-level numeric array property.

Every definition declares a non-zero dimension and one distance metric: cosine,
Euclidean, or Manhattan. Stored embeddings and every query vector must have exactly
the declared dimension.

For background, see [What is vector search?](/learn/vector-search/what-is-vector-search)
and [vector distance metrics](/learn/vector-search/vector-distance-metrics).

Vector search and vector index management are native-only: Cypher and SQL have no
syntax for them. The [Cypher guide](/database/helix-db/query-guides/cypher#what-is-not-supported)
lists what Cypher covers.

## Create a vector index

<CodeGroup>

```rust Rust
write_batch()
    .var_as(
        "index",
        g().create_vector_index_nodes(
            "Doc",
            "embedding",
            std::num::NonZeroUsize::new(3).expect("non-zero dimension"),
            VectorDistanceMetric::Cosine,
            None::<&str>,
        ),
    )
    .returning(["index"]);
```

```ts TypeScript
writeBatch()
  .varAs(

    g().createVectorIndexNodes(
      "Doc",
      "embedding",
      3,
      VectorDistanceMetric.Cosine,
      null,
    ),
  )
  .returning(["index"]);
```

```json JSON
  "query_name": "create_doc_vector_index",
  "query": {
    "write": {
      "entries": [{
        "query": {
          "name": "index",
          "root": {
            "create_index": {
              "spec": {
                "node_vector": {
                  "label": "Doc",
                  "property": "embedding",
                  "dimension": 3,
                  "metric": "cosine"
                }
              },
              "if_not_exists": true
            }
          }
        }
      }],
      "returns": ["index"]
    }
  }
}
```

</CodeGroup>

Pass a tenant property as the final argument to partition the index by tenant. Any
property name works. A record without the tenant property is not indexed. See
[tenant-partitioned search indexes](/database/helix-cloud/operate/multi-tenancy#tenant-partitioned-search-indexes).

Creation returns a receipt before the backfill over existing data finishes. The index
becomes queryable only after validation and atomic activation. Until then, a search that
names it fails with `index_not_found`, as does a search of an index that does not exist.

## Stored vectors

An indexed property accepts an `f32` array, an `f64` array, an `i64` array, or a generic
array of numbers; every value is converted to `f32`. A record without the property is
not indexed. A write fails when the indexed property holds:

| Value | Error |
| --- | --- |
| A different number of components than the index dimension | `invalid_vector_dimension` |
| `NaN`, infinity, or an `f64` too large for `f32` | `invalid_vector_component` |
| All zeros, in a cosine index | `zero_norm_cosine_vector` |
| A component large enough to overflow the Euclidean or Manhattan distance | `vector_component_magnitude_exceeded` |
| Any other type, including `null` | `invalid_query` |

Existing records with such values block a build instead; see
[Troubleshoot index operations](/database/helix-db/query-guides/troubleshooting#index-operation-is-blocked).
A query vector must have the index dimension too. An empty query vector, or one with
`NaN` or infinite components, fails with `invalid_search_input` when it is a literal and
`invalid_query` when it comes from a parameter.

## Search an index

Search the whole index when every record of the label is a valid result. This request
returns the ten `Doc` nodes closest to the query vector:

<CodeGroup>

```rust Rust
read_batch()
    .var_as(
        "hits",
        g().vector_search_nodes("Doc", "embedding", vec![0.1, 0.8, 0.2], 10, None)
            .value_map(Some(vec!["$id", "title", "$distance"])),
    )
    .returning(["hits"]);
```

```ts TypeScript
readBatch()
  .varAs(
    "hits",
    g()
      .vectorSearchNodes("Doc", "embedding", [0.1, 0.8, 0.2], 10, null)
      .valueMap(["$id", "title", "$distance"]),
  )
  .returning(["hits"]);
```

```go Go
helix.ReadQuery("similar_docs").
	VarAs(
		"hits",
		helix.G().
			VectorSearchNodes("Doc", "embedding", []float32{0.1, 0.8, 0.2}, 10).
			ValueMap("$id", "title", "$distance"),
	).
	Returning("hits")
```

```python Python
(
    read_batch()
    .var_as(
        "hits",
        g()
        .vector_search_nodes("Doc", "embedding", [0.1, 0.8, 0.2], 10)

    )
    .returning(["hits"])

```

```json JSON
{
  "request_type": "read",
  "query_name": "similar_docs",
  "query": {
    "read": {
      "entries": [{
        "query": {
          "name": "hits",
          "root": {
            "value_map": {
              "input": {
                "vector_search_nodes": {
                  "label": "Doc",
                  "property": "embedding",
                  "query_vector": { "value": { "f32_array": [0.1, 0.8, 0.2] } },
                  "k": { "literal": 10 }
                }
              },
              "properties": ["$id", "title", "$distance"]
            }
          }
        }
      }],
      "returns": ["hits"]
    }
  }
}
```

</CodeGroup>

Hits arrive closest first, ordered by `$distance` and then by ID. Use
`vectorSearchEdges` / `vector_search_edges` (`VectorSearchEdges` in Go) to search an
edge index. For a tenant-partitioned index, pass the tenant value as the final
argument.

`$distance` exists only on the hit stream: a step to another element drops it, and a
projection ends the traversal. To return it after traversing away, `bind` the hit and
read it with `projectBindings`; see
[Keep search scores after traversing](/database/helix-db/query-guides/projections#keep-search-scores-after-traversing).

`k` must be at least 1: a literal `0` fails with `invalid_search_result_count`, and a
parameter `k` of `0` or less fails with `invalid_query`.

## Distance values

`$distance` is lower for closer vectors under every metric:

| Metric | `$distance` | Range |
| --- | --- | --- |
| Cosine | `(1 - cosine similarity) / 2` | `0` (same direction) to `1` (opposite) |
| Euclidean | Squared Euclidean distance, with no square root | `0` and up |
| Manhattan | Sum of absolute component differences | `0` and up |

Take the square root of a Euclidean `$distance` to get the straight-line distance, and
compute `1 - 2 × $distance` to get the cosine similarity.

## Index structure

Vector indexes are HNSW graphs with fixed settings: `m` 16 (32 on the bottom layer),
`ef_construction` 200, and a search `ef` of `max(k, 100)`. Queries cannot change them.
Results are approximate, so a whole-index search can miss a true nearest neighbor.

## Prefilter with a traversal

To rank only the nodes or edges a traversal reaches, such as documents a user may
access, search within the traversal instead of the whole index. See
[Prefiltered search](/database/helix-db/query-guides/prefiltering#vector-prefiltering).

Search the whole index when every record of the label is a valid answer. Prefilter when
only some records are: filtering whole-index hits afterwards drops results and can leave
fewer than `k`. A small candidate set is also
[ranked exactly](/database/helix-db/query-guides/prefiltering#how-it-works), while a
whole-index search is approximate.

## Combine vector and text search

HelixDB has no operator that fuses vector and BM25 rankings. Run both searches as
entries of one read batch, which reads one snapshot, and merge the two ranked lists in
your application, for example with reciprocal rank fusion:

<CodeGroup>

```rust Rust
read_batch()
    .var_as(
        "semantic",
        g().vector_search_nodes("Doc", "embedding", vec![0.1, 0.8, 0.2], 20, None)
            .value_map(Some(vec!["$id", "$distance"])),
    )
    .var_as(
        "keyword",
        g().text_search_nodes("Doc", "body", "consensus protocol", 20, None)
            .value_map(Some(vec!["$id", "$score"])),
    )
    .returning(["semantic", "keyword"]);
```

```ts TypeScript
readBatch()
  .varAs(
    "semantic",
    g()
      .vectorSearchNodes("Doc", "embedding", [0.1, 0.8, 0.2], 20, null)
      .valueMap(["$id", "$distance"]),
  )
  .varAs(
    "keyword",
    g()
      .textSearchNodes("Doc", "body", "consensus protocol", 20, null)
      .valueMap(["$id", "$score"]),
  )
  .returning(["semantic", "keyword"]);
```

```go Go

	).
	VarAs(
		"keyword",
		helix.G().
			TextSearchNodes("Doc", "body", "consensus protocol", 20).
			ValueMap("$id", "$score"),
	).
	Returning("semantic", "keyword")
```

raw values.

## Search consistency

By default, searches include committed writes that the index worker has not published
into the index yet. A read request can opt into `eventual` search, which bounds that
work per search. See [Search consistency](/database/helix-db/query-guides/search-consistency)
for both modes, searches in write batches, and `index_backpressure`.

## Result limits

The server caps the effective result count of a whole-index search at 800. A narrower
bound from the surrounding plan can lower it. Prefiltered searches have their own
[limits](/database/helix-db/query-guides/prefiltering#result-limits).

## Operational notes

- Creation returns before the backfill necessarily finishes.
- Writes made while an index builds are queued and published after it activates;
  strong searches include them as soon as the index is active. Until then they count
  toward [index backpressure](/database/helix-db/query-guides/search-consistency#index-backpressure).
- Malformed source vectors can block the operation.
- A new generation remains hidden until validation and activation succeed.
- Dropping an index is also a durable lifecycle operation.
