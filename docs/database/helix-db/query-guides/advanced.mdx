`sub()` starts an inline traversal that consumes the current stream. Use it for
branching operations; use `g()` only for a top-level traversal entry.

## Branching operations

| Operation | Behavior |
| --- | --- |
| `optional(sub)` | Keep the input when the branch has no result |
| `union(subs)` | Concatenate results from every branch |
| `choose(predicate, then, else)` | Select one branch |
| `coalesce(subs)` | Use the first non-empty branch |
| `repeat(sub, config)` | Apply a traversal with an explicit bound |

## Retain row-local values

Combine branches with [bindings](/database/helix-db/query-guides/traversals#preserve-correlated-values)
to keep one stable row shape across alternative paths. Bind the starting service, use
`optional` and `union` sub-traversals to bind each candidate workload path, then
project with `projectDistinctBindings` and `coalesce`. See
[Project correlated bindings](/database/helix-db/query-guides/projections#project-correlated-bindings).

## Gate later entries

A batch condition runs an entry only when an earlier entry's result meets a test.
Add the entry with `varAsIf` / `var_as_if` instead of `varAs`. This request returns a
user's posts only when the user exists:

<CodeGroup>

```rust Rust
read_batch()
    .var_as(
        "user",
        g().n_with_label("User")
            .where_(Predicate::eq("username", "alice")),
    )
    .var_as_if(
        "posts",
        BatchCondition::VarNotEmpty("user".to_string()),
        g().n(NodeRef::var("user"))
            .out(Some("AUTHORED"))
            .value_map(Some(vec!["$id", "title"])),
    )
    .returning(["posts"]);
```

```ts TypeScript
readBatch()
  .varAs("user", g().nWithLabel("User").where(Predicate.eq("username", "alice")))
  .varAsIf(
    "posts",
    BatchCondition.varNotEmpty("user"),
    g().n(NodeRef.var("user")).out("AUTHORED").valueMap(["$id", "title"]),
  )
  .returning(["posts"]);
```

```go Go
helix.ReadQuery("user_posts").
	VarAs("user", helix.G().NWithLabel("User").Where(helix.PredEq("username", "alice"))).
	VarAsIf(
		"posts",
		helix.VarNotEmpty("user"),
		helix.G().N(helix.NodeVar("user")).Out("AUTHORED").ValueMap("$id", "title"),
	).
	Returning("posts")
```

```python Python

        g().n(NodeRef.var("user")).out("AUTHORED").value_map(["$id", "title"]),

```

The condition serializes inside the named entry, not as a separate step. Other
conditions test for an empty result (`varEmpty`), a minimum size (`varMinSize`), or
the previous entry (`prevNotEmpty`). The first entry in a batch cannot depend on a
previous result.

## Bound recursive work

Recursive and fan-out operations must have application-level bounds. Prefer explicit
depth, candidate, and response limits. A response `limit` does not necessarily bound
all work performed before that operation.
