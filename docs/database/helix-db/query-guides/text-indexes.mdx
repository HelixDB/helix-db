A text index provides durable BM25 full-text search over a top-level string or
string-array property on nodes or edges. Use it to rank records by exact terms and
keyword relevance.

For background, see [What is full-text search?](/learn/full-text-search/what-is-full-text-search)
and [What is BM25?](/learn/full-text-search/what-is-bm25).

Full-text search and text index management are native-only: Cypher and SQL have no
syntax for them. The [Cypher guide](/database/helix-db/query-guides/cypher#what-is-not-supported)
lists what Cypher covers.

## Create a text index

<CodeGroup>

```rust Rust
write_batch()
    .var_as(
        "index",
        g().create_text_index_nodes("Doc", "body", None::<&str>),
    )
    .returning(["index"]);
```

```ts TypeScript
writeBatch()
  .varAs("index", g().createTextIndexNodes("Doc", "body", null))
  .returning(["index"]);
```

```go Go
helix.WriteQuery("create_doc_text_index").
	VarAs(
		"index",
		helix.G().CreateTextIndexNodes("Doc", "body"),
	).
	Returning("index")
```

```python Python
(
    write_batch()
    .var_as("index", g().create_text_index_nodes("Doc", "body"))
    .returning(["index"])
)
```

```json JSON
{
  "request_type": "write",
  "query_name": "create_doc_text_index",
  "query": {
    "write": {
      "entries": [{
        "query": {
          "name": "index",
          "root": {
            "create_index": {
              "spec": {
                "node_text": {
                  "label": "Doc",
                  "property": "body"
                }
              },
              "if_not_exists": true
            }
          }
        }
      }],
      "returns": ["index"]
    }
  }
}
```

</CodeGroup>

Pass a tenant property as the final argument to partition the index by tenant. Any
property name works. Once the index exists, a write that stores the indexed text on a
record without a tenant value, or with a `null` one, fails with
`invalid_index_source_data`. See
[tenant-partitioned search indexes](/database/helix-cloud/operate/multi-tenancy#tenant-partitioned-search-indexes).

The index becomes queryable only after its build activates. Until then, a search that
names it fails with `index_not_found`.

## Search an index

Search the whole index when every record of the label is a valid result. This request
returns the ten `Doc` nodes that best match `"consensus protocol"`:

<CodeGroup>

```rust Rust
read_batch()
    .var_as(
        "hits",
        g().text_search_nodes("Doc", "body", "consensus protocol", 10, None)
            .value_map(Some(vec!["$id", "title", "$score"])),
    )
    .returning(["hits"]);
```

```ts TypeScript
readBatch()
  .varAs(
    "hits",
    g()
      .textSearchNodes("Doc", "body", "consensus protocol", 10, null)
      .valueMap(["$id", "title", "$score"]),
  )
  .returning(["hits"]);
```

```go Go
helix.ReadQuery("search_docs").
	VarAs(
		"hits",
		helix.G().
			TextSearchNodes("Doc", "body", "consensus protocol", 10).
			ValueMap("$id", "title", "$score"),
	).
	Returning("hits")
```

```python Python
(
    read_batch()
    .var_as(
        "hits",
        g()
        .text_search_nodes("Doc", "body", "consensus protocol", 10)
        .value_map(["$id", "title", "$score"]),
    )
    .returning(["hits"])
)
```

```json JSON
{
  "request_type": "read",
  "query_name": "search_docs",
  "query": {
    "read": {
      "entries": [{
        "query": {
          "name": "hits",
          "root": {
            "value_map": {
              "input": {
                "text_search_nodes": {
                  "label": "Doc",
                  "property": "body",
                  "query_text": { "value": { "string": "consensus protocol" } },
                  "k": { "literal": 10 }
                }
              },
              "properties": ["$id", "title", "$score"]
            }
          }
        }
      }],
      "returns": ["hits"]
    }
  }
}
```

</CodeGroup>

Hits arrive best match first, ordered by BM25 `$score` descending and then by ID. Use
`textSearchEdges` / `text_search_edges` (`TextSearchEdges` in Go) to search an edge
index. For a tenant-partitioned index, pass the tenant value as the final argument.

`$score` exists only on the hit stream: a step to another element drops it, and a
projection ends the traversal. To return it after traversing away, `bind` the hit and
read it with `projectBindings`; see
[Keep search scores after traversing](/database/helix-db/query-guides/projections#keep-search-scores-after-traversing).

## How text matches

The index and the query text go through the same analyzer:

- Text splits into runs of Unicode letters and digits, and each run is lowercased.
  Everything else, including punctuation and hyphens, separates terms, so
  `"Graph-DB v2"` becomes `graph`, `db`, and `v2`.
- There is no stemming and no stopword list: `running` does not match `run`, and `the`
  is a term like any other.
- Query terms are deduplicated and combined with OR, so a document matches when it
  contains any term. BM25 ranks documents with more, rarer terms higher, using fixed
  parameters `k1` 1.2 and `b` 0.75.
- There are no phrase, prefix, wildcard, or fuzzy queries. `"consensus protocol"`
  matches documents with either word, adjacent or not.
- An empty query fails with `invalid_search_input`, or `invalid_query` when it comes
  from a parameter. A query with no letters or digits, such as `"---"`, returns no
  hits.

To combine keyword and semantic ranking, see
[Combine vector and text search](/database/helix-db/query-guides/vector-indexes#combine-vector-and-text-search).

## Prefilter with a traversal

To rank only the nodes or edges a traversal reaches, such as documents a user can
read, search within the traversal instead of the whole index. See
[Prefiltered search](/database/helix-db/query-guides/prefiltering#full-text-search-prefiltering).

## Search consistency

By default, searches include committed writes that the index worker has not published
into the index yet. A read request can opt into `eventual` search, which bounds that
work per search. See [Search consistency](/database/helix-db/query-guides/search-consistency)
for both modes, searches in write batches, and `index_backpressure`.

## Result limits

The server caps the effective result count of a whole-index search at 800.
Prefiltered searches have their own [limits](/database/helix-db/query-guides/prefiltering#result-limits).

## Indexed values

- Store searchable text in a top-level `String` or `StringArray` property.
- `null` and non-string values are rejected. Fix, shorten or delete them before retrying a blocked
  backfill; those writes are accepted while the backfill is blocked.
- Keep tenant property names and values consistent with the definition.
- Keep each document within the [per-document admission limits](/database/helix-cloud/operate/limits#active-text-mutation-admission).
  Writes with longer text fail, and existing longer rows block a backfill with `oversized_entity`.
