The CLI reads instances from the project's `helix.toml`, keeps your Helix Cloud session and its own
state in `~/.helix`, and reads a few environment variables. There is no user-global workspace or
project selection.

## Project file

`helix init` writes `helix.toml` at the project root. Other commands find it by walking up from the
current directory, so they work from any subdirectory; without one they fail with `no helix.toml found`.

Two local instances, one on S3 storage, and a linked Cloud database:

```toml
[project]
name = "my-app"
queries = "db"
container_runtime = "docker"
id = "<project-id>"
workspace_id = "<workspace-id>"

[local.dev]
port = 6969
image = "ghcr.io/helixdb/helixdb"
tag = "v0.0.16"

[local.staging]
port = 7070
image = "ghcr.io/helixdb/helixdb"
tag = "v0.0.16"
storage = "s3"

[local.staging.s3]
bucket = "my-bucket"
prefix = "staging/"
region = "eu-west-2"

[enterprise.production]
database = "tenant:<tenant-id>"
workspace_id = "<workspace-id>"
project_id = "<project-id>"
```

| Table | Count |
| --- | --- |
| `[project]` | Exactly one; required. |
| `[local.<name>]` | One per local instance. |
| `[enterprise.<name>]` | One per linked Helix Cloud database, written by `helix init cloud` and `helix add cloud`. There is no `[cloud.<name>]` table. |

Every command except `helix add` needs at least one local or Cloud instance.

### Instance names

`<name>` is the instance name commands take, as in `helix start dev` or `helix query production`:
1 to 32 ASCII letters, digits, `-`, and `_`. `helix add` refuses a name either table already uses.

Instance names exist only in `helix.toml`, apart from Cloud resource names and slugs: an instance
named `production` can link a Cloud database named `orders`. See
[Targets and resolution](/cli/command-reference#targets-and-resolution).

### `[project]`

| Key | Type | Default | Notes |
| --- | --- | --- | --- |
| `name` | string | Required; `helix init` writes the directory name | Must not be empty. Names local containers, networks, and volumes (`helix-<name>-<instance>`), so renaming it orphans them. `helix project link` never changes it. |
| `container_runtime` | `"docker"` or `"podman"` | `"docker"` | Binary for local instances. |
| `queries` | string (path) | `"db"` | Written by the CLI; no command reads it. |
| `id` | string | Not set | Linked Helix Cloud project ID. Written by `helix init cloud`, `helix add cloud`, `helix project link`, and `helix project create --link`. |
| `workspace_id` | string | Not set | Workspace of the linked project. Written with `id`. |

Cloud commands in the project default to the project in `id`, or, without it, to the `project_id`
that every `[enterprise.*]` table shares.

### `[local.<name>]`

| Key | Type | Default | Notes |
| --- | --- | --- | --- |
| `port` | integer | `6969` | Host port mapped to the container's port `8080`. `helix add local` and `helix init local` do not check it against other instances. |
| `image` | string | `"ghcr.io/helixdb/helixdb"` | Server image repository, without a tag. Set it to run a custom build. |
| `tag` | string | The CLI's default tag (`v0.0.16` for CLI 3.7.0) | 1 to 128 characters (letters, digits, `_`, `.`, `-`; not starting with `.` or `-`), or `sha256:` plus 64 lowercase hex digits to pin a digest. `latest` pulls on every start. See [Image pinning](#image-pinning). |
| `pull` | `"always"`, `"missing"`, or `"never"` | `always` for `latest`, else `missing` | When to pull the server image. `always` needs a successful pull; `never` needs a cached image. An explicit value also applies to the disk-mode SeaweedFS image, which otherwise uses `missing`. |
| `storage` | `"memory"`, `"disk"`, or `"s3"` | `"memory"` | `memory` loses data when the container stops or restarts. `disk` uses a CLI-managed SeaweedFS volume. `s3` uses `[local.<name>.s3]`. |

### `[local.<name>.s3]`

Required when `storage = "s3"`; an error with any other storage mode.

| Key | Type | Default | Notes |
| --- | --- | --- | --- |
| `bucket` | string | Required | Must not be empty. |
| `prefix` | string | `"db/"` | Key prefix for this instance's data. Must not be empty. A leading `/` is dropped and a trailing `/` added. |
| `region` | string | `"us-east-1"` | Must not be empty. |
| `endpoint_url` | string | Not set | S3-compatible endpoint. Must start with `http://` or `https://`. |
| `allow_http` | boolean | `false` | Allow plain HTTP to the endpoint. An `http://` `endpoint_url` allows it too. |

S3 credentials never go in `helix.toml`. `helix start` loads `.env` from the project root and passes
the `AWS_*` [environment variables](#environment-variables) into the container it creates.
`helix restart` keeps the container's original values; run `helix start` to apply new ones.

### `[enterprise.<name>]`

Links a Helix Cloud database by stable ID.

| Key | Type | Default | Notes |
| --- | --- | --- | --- |
| `database` | string | Required | `tenant:<id>` for a tenant database or `cluster:<id>` for a dedicated cluster. The ID is 1 to 128 letters, digits, `-`, and `_`. A shared cluster is not a database target. |
| `project_id` | string | Not set | Project that owns the database. Written by the CLI. |
| `workspace_id` | string | Not set | Workspace that owns the project. Written by the CLI. |

Gateway URLs, application keys, query auth headers or environment variables, sync metadata, and query
bundles have no key here.

### Unknown keys

| Section | Unknown key or table |
| --- | --- |
| Top level, `[project]`, `[enterprise.<name>]` | Rejected: `failed to parse helix.toml at <path>` with `unknown field`. |
| `[local.<name>]`, `[local.<name>.s3]` | Ignored without a warning. |

<Warning>
A misspelled `[local.<name>]` key is ignored: `storge = "disk"` leaves the instance in memory, so its
data is lost when it stops. Check the storage mode in the `ENDPOINT` column of `helix status`.
</Warning>

### Commands that rewrite the file

`helix add`, `helix delete`, `helix start --persist`, `helix project link`, and
`helix project create --link` rewrite the whole file from what the CLI parsed. A rewrite:

- removes every comment;
- writes keys in the CLI's order, and may reorder the instance tables;
- drops unknown keys in `[local.*]` tables;
- writes defaults explicitly, including `queries`, `container_runtime`, `image`, and `tag`.

Keep notes outside `helix.toml`, and review the diff after these commands.

### Image pinning

`helix init local` and `helix add local` write the CLI's current default `image` and `tag`. An
instance keeps that tag after `helix update`; only instances added later get the new default. An
instance without a `tag` key follows the CLI's default until a rewrite writes it.

To move an instance to the image the current CLI ships with:

1. With the instance running, run `helix doctor <instance>`. Its `runtime.image` check reports
   `pins an older server image` and names this CLI's tag.
2. Start on that tag and save it to `[local.dev]`, or edit `tag` by hand and run `helix start dev`:

   ```bash
   helix start dev --image-version v0.0.16 --persist
   ```

   `helix start` replaces the container, so an in-memory instance starts empty.

## Helix home

CLI state lives in `~/.helix` (`%USERPROFILE%\.helix` on Windows), or in `$HELIX_HOME` when set and
not empty.

| Path | Contents |
| --- | --- |
| `credentials` | Your WorkOS session: `access_token`, rotating `refresh_token`, `expires_at`, and `email`. Written atomically, mode `0600` in a `0700` directory on macOS and Linux. Do not edit it or put application keys or service credentials in it. |
| `credentials.lock` | Serializes session refreshes across concurrent `helix` processes. |
| `metrics.toml` | Telemetry level and pseudonymous IDs. See [`helix metrics`](/cli/command-reference/metrics). |
| `update_cache.toml` | Last CLI update check; checks run at most once every 24 hours. |
| `skills_cache.toml` | Last Helix agent skills update check. |
| `ts-runtime/` | TypeScript SDK that `helix query -e` and `--ts-file` install on first use. Under `$HELIX_CACHE_DIR` when set. |

In a project, `.helix/<instance>/` holds per-instance state. `helix init` adds `.helix/` and `.env` to
`.gitignore`.

## Environment variables

| Variable | Effect |
| --- | --- |
| `HELIX_HOME` | Directory for all [Helix home](#helix-home) state. Use a separate one per CI job or test. |
| `HELIX_CACHE_DIR` | Directory for the TypeScript query runtime. Defaults to the Helix home. |
| `HELIX_NO_UPDATE_CHECK` | Any value, even `0`, skips the CLI and skills update checks: a GitHub call, at most once a day, that can delay a command up to 10 seconds. `--json` runs skip them anyway; `helix doctor`'s `cli.version` check still looks up the latest release unless this is set. `HELIX_DISABLE_UPDATE_CHECK` does the same. |
| `NO_COLOR` | Any value turns colors off. Output that is not a terminal is never colored. `CLICOLOR=0` also turns colors off; `CLICOLOR_FORCE=1` forces them on. |
| `CLOUD_AUTHORITY` | Helix Cloud API host. Leave unset to use Helix Cloud. A host without a scheme gets `https://`, or `http://` for `localhost` and `127.0.0.1`. |
| `HELIX_EXPLORER_IMAGE` | Image `helix explorer` runs when `--image` is not passed. |
| `DO_NOT_TRACK` | Any value except empty, `0`, `false`, or `no` turns telemetry off for the CLI and the local instances it starts. |
| `HELIX_TELEMETRY_ENDPOINT` | CLI telemetry endpoint, also passed to the local instances it starts. |
| `HELIX_DEPLOYMENT_ID`, `HELIX_CLUSTER_ID` | Passed to local instances, where they label telemetry. |
| `HELIX_TELEMETRY_LEVEL`, `HELIX_TELEMETRY_INSTALLATION_ID`, `HELIX_TELEMETRY_USER_ID` | Read by a HelixDB server or embedded database, not the CLI. The CLI sets them on local instances from `metrics.toml`. |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`, `AWS_PROFILE`, `AWS_REGION`, `AWS_DEFAULT_REGION` | Passed into local instances that use S3 storage. |
| `DOCKER_HOST`, `DOCKER_CONTEXT` | Select the Docker endpoint. When the daemon is down, they decide whether the CLI starts Docker Desktop, Colima, or OrbStack. |
| `HOME` (`USERPROFILE` on Windows) | Home for `~/.helix` and the default `helix chef` project, `~/my-first-helix-project`. |
| `XDG_STATE_HOME` | Also searched for the `skills` CLI lockfile when checking whether the Helix agent skills are installed. |
