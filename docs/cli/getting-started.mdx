The `helix` CLI scaffolds projects, runs local HelixDB instances, sends queries, and
manages Helix Cloud resources. Local commands need only Docker or Podman; Cloud
commands also need a Helix Cloud account.

## Install

macOS and Linux:

```bash
curl -sSL "https://install.helix-db.com" | bash
```

Windows PowerShell:

```powershell
irm https://raw.githubusercontent.com/HelixDB/helix-db/main/crates/cli/install.ps1 | iex
```

Both installers download the latest release from GitHub and replace an older `helix`. Run
`helix --version` to check, and `helix update` to update later.

<AccordionGroup>
  <Accordion title="Install locations and options (macOS and Linux)">
    The script installs `~/.local/bin/helix`. For bash, zsh, or fish it appends a `PATH` line to
    `~/.bashrc`, `~/.zshrc`, or `~/.config/fish/config.fish` when that file exists and lacks the line;
    restart the shell afterwards. Pass options after `bash -s --`:

    | Option | Effect |
    | --- | --- |
    | `-d`, `--dir <DIR>` | Install into `DIR`. The script does not edit `PATH` for a custom directory. |
    | `-s`, `--system` | Install into `/usr/local/bin`. Needs write access there, so run it with `sudo bash -s -- --system`. |
    | `-f`, `--force` | Reinstall even when the latest version is already installed. |

    ```bash
    curl -sSL "https://install.helix-db.com" | bash -s -- --dir "$HOME/bin"
    ```

    The script always installs the latest release.
  </Accordion>
  <Accordion title="Install locations and options (Windows)">
    The script installs `%LOCALAPPDATA%\Helix\bin\helix.exe` and adds that directory to your user
    `PATH`; open a new PowerShell afterwards. It supports x86-64 Windows. To pass options, run the
    script as a script block:

    ```powershell
    & ([scriptblock]::Create((irm https://raw.githubusercontent.com/HelixDB/helix-db/main/crates/cli/install.ps1))) -Version v3.7.0 -NoPathUpdate
    ```

    | Option | Effect |
    | --- | --- |
    | `-InstallDir <DIR>` | Install into `DIR`. |
    | `-Version <vX.Y.Z>` | Install this release instead of the latest. |
    | `-Force` | Reinstall even when that version is already installed. |
    | `-NoPathUpdate` | Leave the user `PATH` unchanged. |
  </Accordion>
  <Accordion title="Pin a version in CI">
    Release tags are `v<version>`, and each release has one binary per platform:
    `helix-x86_64-unknown-linux-gnu`, `helix-aarch64-unknown-linux-gnu`, `helix-x86_64-apple-darwin`,
    `helix-aarch64-apple-darwin`, and `helix-x86_64-pc-windows-msvc.exe`. On macOS and Linux, download
    the binary directly; on Windows, use `-Version`.

    ```bash
    version=v3.7.0
    target=x86_64-unknown-linux-gnu
    mkdir -p "$HOME/.local/bin"
    curl -fsSL -o "$HOME/.local/bin/helix" \
      "https://github.com/HelixDB/helix-db/releases/download/$version/helix-$target"
    chmod +x "$HOME/.local/bin/helix"
    export PATH="$HOME/.local/bin:$PATH"
    ```

    See [Scripting and CI](/cli/scripting) for JSON output and exit codes.
  </Accordion>
</AccordionGroup>

## Local quickstart

```bash
mkdir my-helix-app && cd my-helix-app
helix init local
helix start dev
helix query dev --file examples/request.json
helix stop dev
```

Local requests use the local auth-disabled runtime. The default storage is in-memory; use `--disk`
or an S3 storage URI when persistence is required. `helix chef` can automate local scaffolding and
agent setup without any Cloud login.

When `helix chef` launches an installed agent, it uses this priority order:
Claude Code → OpenAI Codex → OpenCode → Cursor Agent.

## Cloud quickstart

```bash
helix auth login
mkdir my-cloud-app && cd my-cloud-app
helix init cloud
helix query production -e 'readBatch().varAs("c", g().nWithLabel("User").count()).returning(["c"])'
```

`helix init cloud` picks your workspace, project, and database, using the only one of each or
asking you to choose, and links them in `helix.toml` as the `production` instance. It writes no
example request: `-e` builds one from a TypeScript expression and needs Node.js 20+ and npm. To send
JSON instead, write a request file as described in [Request shape](/cli/command-reference/query#request-shape)
and pass it with `--file`. Later Cloud commands in the directory, such as `helix database` or
`helix logs production`, need no IDs or flags.

Cloud commands use only the rotating WorkOS session. Query execution goes through the backend broker
and requires the `database.query.read` or `database.query.write` permission on the database's
project. The CLI does not need a gateway URL, application key, service credential, or sync step.

When a command cannot choose a resource on its own, pass it by ID, slug, or name, for example
`helix database list --project <project>` or `helix query tenant:<id> --file request.json`. Stable
links live only in the current project's `helix.toml`. See
[Cloud resource resolution](/cli/command-reference#cloud-resource-resolution).
