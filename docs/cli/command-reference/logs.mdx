Show container logs for a local instance, or list recent query errors for a Helix Cloud database.
Local and Cloud.

## Usage

```bash
helix logs [INSTANCE] [--follow]
helix logs [CLOUD_INSTANCE] [--start <RFC3339>] [--end <RFC3339>]
```

## Arguments

| Argument | Description |
| --- | --- |
| `INSTANCE` | Instance name from `helix.toml`. If omitted, the CLI uses `dev`, then the only instance, then a picker in a terminal; otherwise it fails and lists the instances. |

## Options

| Flag | Description | Default |
| --- | --- | --- |
| `-f`, `--follow` | Local only: keep streaming new log lines. | Off |
| `--start <TIME>` | Cloud only: start of the window, as an RFC 3339 timestamp. | One hour before `--end` |
| `--end <TIME>` | Cloud only: end of the window, as an RFC 3339 timestamp. | Now |
| `--json` | Cloud only: print the query errors as a JSON array. | Off |

## Behavior

- Local logs are plain text from Docker/Podman and may follow. `--start`, `--end`, and `--json` are rejected for local instances.
- Cloud logs use the WorkOS session and the linked database's recent query-error endpoint on the Helix Cloud API; they never contact the database gateway that applications use.
- Cloud errors print as a table with `TIME`, `QUERY`, and `ERROR` columns. An empty window prints a message naming the instance and time range.
- `--start` must be before `--end`. Without either, the window is the last hour.
- Cloud follow is not supported.

## Examples

```bash
# Print the logs of the local 'dev' instance
helix logs dev

# Follow local logs
helix logs dev --follow

# Recent query errors for a Cloud instance (last hour)
helix logs production

# Query errors in an explicit window, as JSON
helix logs production --start 2026-01-01T00:00:00Z --end 2026-01-01T06:00:00Z --json
```
