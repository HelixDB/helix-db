Show container logs for a local instance, or list recent query errors for a Helix Cloud database.
Local and Cloud.

## Usage

```bash
helix logs [INSTANCE] [--follow]
helix logs [CLOUD_INSTANCE] [--range [--start <RFC3339>] [--end <RFC3339>]]
```

## Arguments

| Argument | Description |
| --- | --- |
| `INSTANCE` | Instance name from `helix.toml`. If omitted, the CLI prompts in a TTY when there are several instances; otherwise it uses `dev` or the only instance. |

## Options

| Flag | Description | Default |
| --- | --- | --- |
| `-f`, `--follow` | Local only: keep streaming new log lines. | Off |
| `-r`, `--range` | Cloud only: enable `--start` and `--end`. | Off |
| `--start <TIME>` | Cloud only: start of the range, as an RFC 3339 timestamp. Requires `--range`. | One hour before `--end` |
| `--end <TIME>` | Cloud only: end of the range, as an RFC 3339 timestamp. Requires `--range`. | Now |

## Behavior

- Local logs use Docker/Podman and may follow. `--range`, `--start`, and `--end` are rejected for local instances.
- Cloud logs use the WorkOS session and the linked database's recent query-error endpoint on the Helix Cloud API; they never contact the database gateway that applications use.
- Each Cloud error prints as one line: timestamp, query name, and error output.
- Cloud follow is not supported.
- Without explicit times, the Cloud range is the last hour.

## Examples

```bash
# Print the logs of the local 'dev' instance
helix logs dev

# Follow local logs
helix logs dev --follow

# Recent query errors for a Cloud instance (last hour)
helix logs production

# Query errors in an explicit window
helix logs production --range --start 2026-01-01T00:00:00Z --end 2026-01-01T06:00:00Z
```
