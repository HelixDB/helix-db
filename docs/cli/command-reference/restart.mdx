Restart an existing background local instance in place. Local only.

## Usage

```bash
helix restart [INSTANCE]
```

## Arguments

| Argument | Description |
| --- | --- |
| `INSTANCE` | Local instance to restart. If omitted in a TTY with multiple instances, the CLI prompts. Defaults to `dev` when present, otherwise the only local instance. |

## Behavior

- Restarts the existing container with its current image and container settings. It never pulls an image or creates a replacement container.
- If the container has been removed (for example after `helix stop` or `helix prune`), the command fails. Use [`helix start`](/cli/command-reference/start) to create a container.
- Readiness is checked with `GET /healthz` on the container's published port, including a temporary `helix start --port` override.
- Default local data is in-memory and is wiped by every restart. Disk-mode instances keep data in their local MinIO volume, and S3 data is never deleted.
- `restart` takes no overrides. To change the image, port, or storage mode, use `helix start`, adding `--persist` to save the change.

## Examples

```bash
# Restart the default 'dev' instance
helix restart dev

# Restart with interactive picker
helix restart
```
