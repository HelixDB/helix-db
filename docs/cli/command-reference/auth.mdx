Manage the WorkOS login session that every Helix Cloud command uses. Cloud only; local commands
never need it.

## Usage

```bash
helix auth login [github | google | microsoft | sso | password]
helix auth status
helix auth logout
```

## Subcommands

| Subcommand | Description |
| --- | --- |
| `login` | Sign in with any supported method and store the session. Asks which method when you do not name one. |
| `status` | Verify the session and show the signed-in email and your workspaces by name. |
| `logout` | Revoke the session when possible and delete the local credential file. |

## Login methods

| Method | How it signs in |
| --- | --- |
| `github`, `google`, `microsoft` | Continue with that provider in your browser. |
| `sso [--email <email>]` | Single sign-on through the identity provider of your company's verified email domain, in your browser. Asks for the work email when omitted. |
| `password [--email <email>]` | Email and password, in the terminal. Asks for the email when omitted, and always reads the password from a hidden prompt. |

## Options

| Flag | Description | Default |
| --- | --- | --- |
| `--json` | Print the result as JSON on stdout and never prompt. `status` prints `{"email":"...","workspaces":[{"id":"...","name":"..."}]}`. | Off |

## Behavior

### Login

- `login` requires an interactive terminal, so it fails with `--json`.
- Browser methods start WorkOS PKCE in a browser (and print the URL in case the browser does not open), then show a spinner while they wait for the loopback callback on `http://localhost:8765/callback`. The login times out after 5 minutes.
- `password` signs in with an existing account. To create an account or reset a password, use [the sign-in page](https://helix-db.com/login).
- If your company requires single sign-on, any method continues through its identity provider in the browser.
- If WorkOS requires email verification, the CLI prompts for the code and accepts up to three attempts.
- It hydrates all current workspace memberships and stores only the rotating WorkOS session in `~/.helix/credentials` (or `$HELIX_HOME/credentials`).

### Session handling

- The CLI refreshes tokens within 60 seconds of expiry and serializes refreshes across processes.
- The credential file is mode `0600` and rejects old key fields.
- Cloud commands do not accept environment API keys, service credentials, legacy user/admin keys, or custom authorization headers.

### Status and logout

- `status` verifies the session by listing your workspaces through the Helix Cloud API, then prints `Email` and `Workspaces` (by name).
- `logout` asks the Helix Cloud API to revoke the session when possible and always deletes the local file.

## Examples

```bash
# Choose how to sign in
helix auth login

# Sign in with a specific method
helix auth login google
helix auth login sso --email you@company.com
helix auth login password --email you@company.com

# Check who is signed in
helix auth status

# Sign out and delete the local session
helix auth logout
```
