Create and manage service credentials: workspace-owned secrets that let headless automation call
Helix Cloud. You manage them with your WorkOS login, but they never log the CLI in. Cloud only.

Owners and admins need the workspace-scoped `service_credentials.manage` permission.

## Usage

```bash
helix service-credential create --workspace <id> --name <name> \
  --grant <project-id>=project-read,query-read [--expires-at <RFC3339>]
helix service-credential list --workspace <id>
helix service-credential get --workspace <id> <credential-id>
helix service-credential update --workspace <id> <credential-id> \
  [--name <name>] [--grant <project-id>=query-read,query-write] \
  [--expires-at <RFC3339> | --clear-expiry]
helix service-credential revoke --workspace <id> <credential-id> [--yes]
```

## Subcommands

| Subcommand | Description |
| --- | --- |
| `create` | Create a credential and print its secret once. |
| `list` | List credentials owned by a workspace. |
| `get` | Show one credential. Its secret is never returned. |
| `update` | Change the name, expiry, or project grants without rotating the secret. |
| `revoke` | Revoke a credential. |

## Arguments

| Argument | Description |
| --- | --- |
| `CREDENTIAL_ID` | Credential to act on with `get`, `update`, or `revoke`. Required. |

## Options

| Flag | Description | Default |
| --- | --- | --- |
| `--workspace <ID>` | Owning workspace. Required for every subcommand. | — |
| `--name <NAME>` | Credential name. Required for `create`. | — |
| `--grant <PROJECT_ID>=<PERMISSIONS>` | Project grant, repeatable. `create` needs at least one; on `update`, any `--grant` replaces all existing grants. | — |
| `--expires-at <RFC3339>` | Expiry time for `create` or `update`. | No expiry |
| `--clear-expiry` | `update`: remove the expiry. Conflicts with `--expires-at`. | Off |
| `-y`, `--yes` | `revoke`: skip the confirmation prompt. Required in non-interactive shells. | Off |
| `--format <FORMAT>` | `list`, `get`: `human` or `json`. | `human` |

## Behavior

- Each grant is project-scoped and must name a project inside the owning workspace.
- Available grants are `project-read`, `project-write`, `query-read`, and `query-write`, comma-separated; write requires its matching read.
- Each project may appear in only one `--grant`, and a grant cannot repeat a permission.
- Creation displays the secret once. Updates never reveal or rotate it.
- `update` needs at least one of `--name`, `--grant`, `--expires-at`, or `--clear-expiry`.
- Service credentials authenticate headless HTTP API calls and the unified MCP endpoint at `https://mcp.helix-db.com/mcp`.
- MCP exposes only the query and customer administration tools their project grants allow. These sessions do not get Cloud discovery or observability tools.
- They are never a CLI login method and the CLI never persists them.

## Examples

```bash
# Create a read-only credential for one project, expiring at the end of the year
helix service-credential create --workspace <id> --name ci-reader \
  --grant <project-id>=project-read,query-read --expires-at 2026-12-31T23:59:59Z

# Allow the credential to write queries too (replaces all grants)
helix service-credential update --workspace <id> <credential-id> \
  --grant <project-id>=project-read,query-read,query-write

# Revoke it without a prompt
helix service-credential revoke --workspace <id> <credential-id> --yes
```
