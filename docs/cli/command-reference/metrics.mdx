Configure CLI telemetry and usage metrics collection. Settings are stored in the per-user metrics
config and apply to every project on this machine.

## Usage

```bash
helix metrics <SUBCOMMAND>
```

## Subcommands

| Subcommand | Description |
| --- | --- |
| `full` | Enable full metrics collection (prompts for an email address). |
| `basic` | Enable minimal anonymous metrics. |
| `off` | Disable all metrics collection. |
| `status` | Show current metrics configuration and when it was last updated. |

## Options

| Flag | Description | Default |
| --- | --- | --- |
| `--json` | Print the result as JSON on stdout. `status` prints `level`, `userId`, and `lastUpdated` (Unix seconds); the others print `level`. | Off |

## Behavior

- The setting is saved in `~/.helix/metrics.toml` (or `$HELIX_HOME/metrics.toml`).
- `full` asks for an email address in a terminal and validates it before saving. Without a terminal, or with `--json`, it reads the address from piped stdin, one line at a time, until a valid one arrives, for example `echo you@example.com | helix metrics full --json`. If stdin is a terminal in that case, as with `--json` typed in a shell, it fails and asks you to pipe the address.
- Local instances started by the CLI receive the same telemetry level.
- `DO_NOT_TRACK` set to anything but empty, `0`, `false` or `no` turns telemetry off for the CLI and the instances it starts, whatever the saved level.
- `HELIX_TELEMETRY_LEVEL` sets the level of a server or embedded database: `full`, `basic` (or `on`, `true`, `yes`, `1`) or `off` (or `false`, `no`, `0`).
- `basic` identifies the sender only by pseudonymous IDs: a random installation ID, a hash of the git repository, and `HELIX_DEPLOYMENT_ID` or a hash of the S3 bucket. Query events carry each query's shape with every value redacted, its latency and outcome, and the first word of the caller's `User-Agent`. No repository or bucket names, parameters, results or IP addresses are stored.

### `helix metrics status` output

`status` prints `Level` (`full`, `basic`, or `off`), `User ID` (if set), and a relative `Last updated` time:

| Age | Format |
| --- | --- |
| 0–4 seconds | `just now` |
| 5–59 seconds | `<n>s ago` |
| 1–59 minutes | `<n>m ago` |
| 1–23 hours | `<n>h ago` |
| 1+ days | `<n>d ago` |

## Examples

```bash
# Enable full metrics (prompts for email)
helix metrics full

# Enable anonymous basic metrics
helix metrics basic

# Disable all metrics
helix metrics off

# Show current state
helix metrics status
```
